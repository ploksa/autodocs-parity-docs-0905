The demo's tests use Node's built-in `node:test` runner via `tsx --test`, orchestrated by [glob](https://github.com/isaacs/node-glob) and covered by [c8](https://github.com/bcoe/c8). They exercise a real Fastify instance against a live MySQL database.

## Run the suite

```bash
npm run test
```

Which expands to (from `package.json`):

```text
npm run db:seed && c8 npm run test:run
# test:run: glob -c "tsx --test" "./test/**/*.ts"
```

`db:seed` requires `CAN_SEED_DATABASE=1`. In CI this is set by the workflow (see [CI](/operations/ci)).

## Test helper

Source: [`test/helper.ts`](https://github.com/fastify/demo/blob/main/test/helper.ts).

- `build(t?)`: builds a Fastify instance with `serviceApp` registered as a plugin. When a `TestContext` is passed, the instance is closed after the test.
- `login(email)`: posts to `/api/auth/login` with the seeded password `Password123$` and returns the session cookie value.
- `injectWithLogin(email, opts)`: convenience that logs in and then calls `fastify.inject` with the session cookie attached.
- `expectValidationError(res, message)`: asserts `status 400` and body `{ message }`.
- `config()`: returns `{ skipOverride: true }` so `serviceApp` is registered with `fastify-plugin` semantics.

## Environment for tests

The demo expects a MySQL instance reachable with the same env vars as production. In local dev, run `docker compose up -d` first. In CI, MySQL is started as a service (see [CI](/operations/ci)).

Set `RATE_LIMIT_MAX=4` for tests, per the comment in `.env.example`, so that rate-limit tests can trip the limit cheaply.
