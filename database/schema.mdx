The schema is created by SQL migrations in [`migrations/`](https://github.com/fastify/demo/tree/main/migrations). Each migration has a matching `undo` script.

## `users`

Source: [`migrations/001.do.users.sql`](https://github.com/fastify/demo/blob/main/migrations/001.do.users.sql).

```sql
CREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  username VARCHAR(255) NOT NULL,
  password VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

`password` stores a scrypt hash in the `"<salt-hex>.<hash-hex>"` format produced by [`passwordManager.hash`](/architecture/plugins#password-manager-ts).

## `tasks`

Source: [`migrations/002.do.tasks.sql`](https://github.com/fastify/demo/blob/main/migrations/002.do.tasks.sql).

```sql
CREATE TABLE tasks (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  author_id INT NOT NULL,
  assigned_user_id INT,
  filename VARCHAR(255),
  status VARCHAR(50) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (author_id) REFERENCES users(id),
  FOREIGN KEY (assigned_user_id) REFERENCES users(id)
);
```

Task `status` is a free-form `VARCHAR(50)` at the database level. In application code (`src/schemas/tasks.ts`) it is restricted to: `new`, `in-progress`, `on-hold`, `completed`, `canceled`, `archived`.

`filename` stores the name of an uploaded image. Files are written to `${UPLOAD_DIRNAME}/${UPLOAD_TASKS_DIRNAME}/` (default `uploads/tasks/`).

## `user_tasks`

Source: [`migrations/003.do.user_tasks.sql`](https://github.com/fastify/demo/blob/main/migrations/003.do.user_tasks.sql).

```sql
CREATE TABLE user_tasks (
  user_id INT NOT NULL,
  task_id INT NOT NULL,
  PRIMARY KEY (user_id, task_id),
  FOREIGN KEY (user_id) REFERENCES users(id),
  FOREIGN KEY (task_id) REFERENCES tasks(id)
);
```

<Note>
  The `user_tasks` table is created by migration `003` but no source file at this commit reads from or writes to it. Assignment is stored directly on `tasks.assigned_user_id` by `POST /api/tasks/:id/assign`.
</Note>

## `roles`

Source: [`migrations/004.do.roles.sql`](https://github.com/fastify/demo/blob/main/migrations/004.do.roles.sql).

```sql
CREATE TABLE roles (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(255) NOT NULL
);
```

## `user_roles`

Source: [`migrations/005.do.user_roles.sql`](https://github.com/fastify/demo/blob/main/migrations/005.do.user_roles.sql).

```sql
CREATE TABLE user_roles (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL,
  role_id INT NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (role_id) REFERENCES roles(id) ON DELETE CASCADE
);
```

Role names read by the application are `admin`, `moderator`, and `basic` (see [Authorization](/auth/authorization) and [`scripts/seed-database.ts`](https://github.com/fastify/demo/blob/main/scripts/seed-database.ts)).
